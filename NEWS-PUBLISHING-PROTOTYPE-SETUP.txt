IMPORTANT: NOT YET A LIVE WORKING SERVICE
GitHub Pages cannot execute the API routes. A Vercel (or equivalent Node serverless) deployment is required. The source changes are committed to the test branch, but hosting, OAuth configuration and end-to-end browser testing have not been completed.

HOSTING SETUP REQUIRED BEFORE USER TEST
1. Create a Vercel project connected to echscoregroup/echs-help-24x7.
2. Select HH-WEBSITE-PUBLISHING-TEST-1.0.4 as the Vercel deployment branch. Do not change GitHub Pages settings.
3. Obtain the stable HTTPS deployment URL and set APP_BASE_URL to that exact URL.
4. Configure a GitHub OAuth-capable app/client with callback:
   APP_BASE_URL + /api/auth/callback
   It must be authorised to write contents to the public repository. The sign-in flow requests public_repo scope.
5. Set Vercel environment variables:
   APP_BASE_URL = exact HTTPS Vercel deployment URL
   GITHUB_APP_CLIENT_ID = OAuth client ID
   GITHUB_APP_CLIENT_SECRET = OAuth client secret
   ADMIN_GITHUB_LOGIN = exact authorised GitHub login
   SESSION_SECRET = long random secret (at least 32 random bytes)
6. Redeploy the Vercel project after setting environment variables.
7. Keep the Vercel project and deployment URL private until administrator sign-in and write permissions are verified. The website itself is public.

LIMITATIONS / OPEN ITEMS
- The old browser-local test data is not automatically transferred between the GitHub Pages origin and the new Vercel origin. Before first live test, export/import any locally tested records that must be preserved; do not overwrite tested records.
- PDF upload and metadata publish are separate commits. If metadata publish fails after upload, the uploaded PDF may remain unused in published-files/ and can be cleaned up after verification.
- The API writes one JSON file per box; it does not write to ECHSHELP or any production branch.
- A successful GitHub commit is not sufficient acceptance. Cross-browser visitor visibility and visual regression tests are mandatory.
